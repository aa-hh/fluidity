# AA-295: What FluidAudio provides, and how open-source Mac dictation apps handle the hotkey, pasting and the clipboard

Read on 23 October 2026, against each repository's default branch (`main`). Line numbers point at that day's files and will drift. Every claim links to the file it came from. Where a doc and the code disagree, the code wins and the doc is flagged.

## Short answer

- FluidAudio (Apache-2.0, macOS 14+) gives us model download and caching, Parakeet TDT v2 batch transcription, vocabulary boosting, Silero voice activity detection and a command-line transcriber. It does not capture the microphone, and it has no dictation sample app.
- Live preview: for short dictation, FluidAudio's built-in sliding-window manager shows no text until 13 seconds of audio exist. Two apps (Dictate Anywhere, VoiceTypr) instead re-run batch Parakeet on the growing buffer about once a second. FluidAudio pads every clip up to 15 s, so a re-run costs the same whatever the clip length. That is the approach to copy. The Parakeet EOU streaming model is the alternative; it is a different, smaller model (120M parameters) with higher error rates.
- Vocabulary boosting with Parakeet TDT 0.6B v2 means loading a second 97.5 MB model (Parakeet CTC 110M) and rescoring the finished transcript. FluidAudio reports it at 26x real time against 70x for the smaller hybrid model. It is tested up to 230 terms.
- Hotkey: every app that supports Fn uses a `CGEvent` tap that watches `flagsChanged` events for `kVK_Function` / `.maskSecondaryFn`. Carbon `RegisterEventHotKey` cannot see Fn.
- Inserting text: every Mac app here pastes through the clipboard. Most send a synthetic Cmd-V; Dictate Anywhere first presses the target app's own Edit > Paste menu item through Accessibility. The careful ones check that focus has not moved first, fall back to typing Unicode key events, and never auto-paste a line break into a terminal.
- Clipboard: the good pattern is snapshot all items and types, write the transcript, paste, then restore only if the clipboard still holds our transcript. Fixed restore delays across the apps range from 200 ms to 2 s, and Parakey dropped automatic restore entirely because a slow app could paste the old clipboard.
- Reading text back after pasting to learn the user's edits: only VoiceInk and Fluid-oss do it, and both are GPL-3.0, so we can copy the idea but not the code.
- Licences: Hex, Starling, MiniWhisper, Dictate Anywhere, Parakey, VivaDicta are MIT. Super Voice Assistant is MIT except images and name. VoiceInk and Fluid-oss are GPL-3.0. VoiceTypr is AGPL-3.0.

### Batch transcription (what Fluidity's final text will use)

- `AsrModels.downloadAndLoad(version: .v2)` then `AsrManager(config:models:)`. `transcribe` takes `[Float]` at 16 kHz, an `AVAudioPCMBuffer` or a file URL. Every overload also needs `decoderState: inout TdtDecoderState`. [AsrManager.swift#L410-L558](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/TDT/AsrManager.swift#L410-L558)
- Clips of 15 s or less are padded to exactly 15 s (240,000 samples) and decoded in one pass. Longer clips go to `ChunkProcessor`. Clips under 0.3 s throw `invalidAudioData`. [AsrManager+Transcription.swift#L9-L38](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/TDT/AsrManager+Transcription.swift#L9-L38), [ASRConstants.swift](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/Shared/ASRConstants.swift)
- `ASRResult` carries `text`, `confidence` and `tokenTimings`. Vocabulary rescoring needs the token timings. [VocabularyBoostingSession.swift#L108-L113](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/VocabularyBoostingSession.swift#L108-L113)
- The docs recommend v2 for English-only work: "better recall on long-form English audio". [Documentation/ASR/GettingStarted.md#L19](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/GettingStarted.md#L19)
- Stale docs: the README quick start calls `asrManager.transcribe(samples)` with no decoder state, which matches no current method. [README](https://github.com/FluidInference/FluidAudio/blob/main/README.md)

### Vocabulary boosting (personal word list)

- How it works: a separate CTC model (Parakeet CTC 110M) produces per-frame probabilities. A keyword spotter scores each term against them, and a rescorer swaps words in the TDT transcript only where the term has stronger acoustic evidence. The technique comes from NVIDIA NeMo, arXiv:2406.07096. [Documentation/ASR/CustomVocabulary.md#L1-L25](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/CustomVocabulary.md#L1-L25)
- With TDT 0.6B v2 it must load the separate 97.5 MB CTC encoder ("Approach 2"). The doc reports 25.98x real time against 70.29x for the TDT-CTC-110M model's built-in head, the same 99.4% dictionary recall for both, and about 130 MB against 67 MB peak memory. [CustomVocabulary.md#L20-L25, #L174-L195](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/CustomVocabulary.md#L174-L195)
- API for batch use: `CtcModels.downloadAndLoad()`, then `VocabularyBoostingSession(vocabulary:ctcModels:config:)`, then `session.rescore(text:tokenTimings:audioSamples:)` after `AsrManager.transcribe`. It returns `nil` when nothing changed. It swallows its own errors ("boosting must never break transcription"). [VocabularyBoostingSession.swift#L45-L168](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/VocabularyBoostingSession.swift#L45-L168). Dictate Anywhere calls it this way. [PreparedTDTVocabulary.swift#L17-L37](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/main/Dictate%20Anywhere/PreparedTDTVocabulary.swift#L17-L37)
- `hasCTCRescoringCandidates(text:tokenTimings:)` is a cheap check that skips the CTC pass when no term could match. [VocabularyBoostingSession.swift#L89-L95](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/VocabularyBoostingSession.swift#L89-L95)
- Terms: `CustomVocabularyTerm(text:aliases:)`. The text file format is one term per line, optionally `word: alias1, alias2`, with `#` for comments. [CustomVocabularyContext.swift#L228-L240](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/CustomVocabulary/CustomVocabularyContext.swift#L228-L240)
- Size: 1–50 terms "Excellent", 50–100 "No noticeable latency impact", 100–230 "Tested". Terms should be at least 4 characters, and stopwords are skipped. Matching thresholds tighten automatically above 10 and above 100 terms. [CustomVocabulary.md#L492-L522, #L741-L753](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/CustomVocabulary.md#L741-L753)
- Trap: short terms that sound like ordinary English (acronyms, short brand names) cause false replacements. FluidAudio measured about 94 false hits with the default settings and about 19 with `VocabularyRescorer.Config(spotterRescueEnabled: false)`. [CustomVocabulary.md#L614-L659](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/CustomVocabulary.md#L614-L659)
- Stale docs: the doc's "Usage Example" calls `asrManager.transcribe(audioSamples, customVocabulary:)`. That method does not exist on `AsrManager` today. Upstream `configureVocabularyBoosting` exists only on `SlidingWindowAsrManager`, `UnifiedAsrManager` and `StreamingUnifiedAsrManager` (GitHub code search). [CustomVocabulary.md#L661-L684](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/ASR/CustomVocabulary.md#L661-L684), [SlidingWindowAsrManager.swift#L100-L114](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/SlidingWindowAsrManager.swift#L100-L114)
- Practical note from Fluid-oss: it keeps one `AsrManager` without boosting for previews and a second one with boosting for the final pass. Their comment says running both on one manager "causes intermittent SIGTRAP crashes during streaming inference". Fluid-oss pins its own FluidAudio fork, so this may not apply upstream. [FluidAudioProvider.swift#L583-L604](https://github.com/altic-dev/Fluid-oss/blob/main/Sources/Fluid/Services/FluidAudioProvider.swift#L583-L604), [Package.swift#L14](https://github.com/altic-dev/Fluid-oss/blob/main/Package.swift#L14)

### Voice activity detection

Silero VAD v6.2.1 converted to Core ML, judged on 256 ms windows. `VadManager.process(samples)` returns a probability per chunk. `segmentSpeech(samples, config:)` returns speech segments. `processStreamingChunk(_:state:config:)` returns `speechStart` / `speechEnd` events for live audio. [README "Voice Activity Detection"](https://github.com/FluidInference/FluidAudio/blob/main/README.md), [Documentation/VAD/GettingStarted.md#L3-L39](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/VAD/GettingStarted.md). MiniWhisper and Dictate Anywhere use it to trim silence and decide when a preview is worth running. [MiniWhisper VADPreprocessor.swift](https://github.com/andyhtran/MiniWhisper/blob/main/Sources/MiniWhisper/Services/VADPreprocessor.swift), [Dictate Anywhere BatchSpeechDetection.swift](https://github.com/hoomanaskari/mac-dictate-anywhere/blob/main/Dictate%20Anywhere/BatchSpeechDetection.swift)

### Command-line tool for scoring ~270 recordings

- `swift run fluidaudiocli transcribe <file> --model-version v2 --output-json out.json` handles one file per run. It prints full text, confidence and word timings. `--custom-vocab terms.txt` turns on boosting in batch mode, and the `--vocab-*` flags tune it. `--local-model-dir` never downloads. The CLI is macOS only. [TranscribeCommand.swift#L1165-L1232](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudioCLI/Commands/ASR/Parakeet/SlidingWindow/TranscribeCommand.swift#L1165-L1232), [README FAQ](https://github.com/FluidInference/FluidAudio/blob/main/README.md)
- `multi-stream a.wav b.wav` transcribes several files at once. [Documentation/CLI.md#L58-L59](https://github.com/FluidInference/FluidAudio/blob/main/Documentation/CLI.md#L58-L59)
- `asr-benchmark` only runs on LibriSpeech subsets, so it cannot score our recordings directly. Its `WERCalculator` (word and character error rate with Hugging Face-compatible text normalisation) is reusable for our scoring script. [AsrBenchmark.swift#L353-L357, #L660-L740](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudioCLI/Commands/ASR/Parakeet/SlidingWindow/AsrBenchmark.swift)
- Ready-made example: Parakey (MIT) ships a Swift benchmark that runs `AsrManager`, `VocabularyBoostingSession`, `SlidingWindowAsrManager` and `UnifiedAsrManager` over a folder of recordings, with Python harness scripts around it. [experiments/swift-bench/Sources/presspeech-bench/main.swift#L685-L1113](https://github.com/rcourtman/parakey/blob/main/experiments/swift-bench/Sources/presspeech-bench/main.swift), [experiments/swift-bench/](https://github.com/rcourtman/parakey/tree/main/experiments/swift-bench)

### Hex — kitlangton/Hex (MIT, archived)

The README says "Hex has moved to anomalyco/hex… This Swift app is no longer maintained". The new app is Rust, also MIT. [README](https://github.com/kitlangton/Hex/blob/main/README.md)

- **Hotkey.** One `CGEvent.tapCreate(tap: .cghidEventTap, place: .headInsertEventTap, options: .defaultTap)` watches key down/up, `flagsChanged` and mouse clicks. [KeyEventMonitorClient.swift#L416-L428](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/KeyEventMonitorClient.swift#L416-L428). Fn: on `flagsChanged` with `keyCode == kVK_Function`, it reads `flags.contains(.maskSecondaryFn)`. [#L574-L577](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/KeyEventMonitorClient.swift#L574-L577). Modifier-only hotkeys throw away presses under 0.3 s so a quick Option tap for a special character does not record. [docs/hotkey-semantics.md](https://github.com/kitlangton/Hex/blob/main/docs/hotkey-semantics.md). It treats an event arriving at the tap as proof of permission, because `IOHIDCheckAccess` can report a stale denial (their issue #250). [#L106-L167, #L532-L542](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/KeyEventMonitorClient.swift#L532-L542)
- **Inserting text.** It writes the transcript, waits up to 150 ms for `changeCount` to advance, then tries Cmd-V, the Edit > Paste menu item via AppleScript, and Accessibility `kAXSelectedTextAttribute`, in that order. [PasteboardClient.swift#L203-L297](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/PasteboardClient.swift#L203-L297). Bug: `postCmdV` always returns `true`, so the two fallbacks are never reached. [#L302-L319](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/PasteboardClient.swift#L302-L319). The alternative mode types through AppleScript `keystroke` and only escapes `"`. [#L333-L341](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/PasteboardClient.swift#L333-L341). The settings text admits it: "Fast but may not restore all clipboard content". [GeneralSectionView.swift#L36-L42](https://github.com/kitlangton/Hex/blob/main/Hex/Features/Settings/GeneralSectionView.swift#L36-L42)
- **Clipboard.** It snapshots every item and every type as `Data`, and restores 500 ms after a successful paste unless the user chose "Copy to clipboard". It does not check whether something else wrote to the clipboard in the meantime. [PasteboardClient.swift#L52-L81, #L214-L223](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/PasteboardClient.swift#L52-L81)
- **Overlay.** `class InvisibleWindow: NSPanel` with `[.borderless, .utilityWindow, .nonactivatingPanel]`, `level = .statusBar`, `ignoresMouseEvents`, `hidesOnDeactivate = false`, `collectionBehavior = [.fullScreenAuxiliary, .canJoinAllSpaces, .stationary, .ignoresCycle]`. [InvisibleWindow.swift#L17-L40](https://github.com/kitlangton/Hex/blob/main/Hex/Views/InvisibleWindow.swift#L17-L40)
- **Permissions.** Microphone via `AVCaptureDevice.requestAccess`. Accessibility via `AXIsProcessTrustedWithOptions` (checks silently first, prompts only when asked). Input Monitoring via `IOHIDCheckAccess` / `CGRequestListenEventAccess`. Each has a deep link into System Settings. [PermissionClient+Live.swift#L73-L170](https://github.com/kitlangton/Hex/blob/main/HexCore/Sources/HexCore/PermissionClient/PermissionClient+Live.swift#L73-L170)
- **Speech.** Batch only. It records a WAV, pads clips shorter than 1.5 s with silence, then calls `AsrManager.transcribe(url, decoderState:)`. No live preview. [ParakeetClient.swift#L81-L128](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/ParakeetClient.swift), [ParakeetClipPreparer.swift#L38](https://github.com/kitlangton/Hex/blob/main/Hex/Clients/ParakeetClipPreparer.swift#L38)

### Starling — Ryandonofrio3/Starling (MIT; last push October 2025)

- **Hotkey.** Carbon `RegisterEventHotKey` with `kEventHotKeyPressed` / `kEventHotKeyReleased` for hold-to-talk. [HotkeyManager.swift#L145-L196](https://github.com/Ryandonofrio3/Starling/blob/main/Starling/Application/HotkeyManager.swift#L145-L196). Carbon needs a non-modifier key, so Fn is not possible.
- **Inserting text.** Cmd-V via `CGEvent` at `.cghidEventTap`. Text with line breaks is pasted in pieces with a synthetic Return between them. [PasteController.swift#L124-L224](https://github.com/Ryandonofrio3/Starling/blob/main/Starling/Paste/PasteController.swift#L124-L224). Before pasting, it compares a snapshot of the focused element taken when recording started. If focus moved, or secure input is on (read from `CGSSessionCopyCurrentDictionary()["CGSSessionSecureInputPID"]`), it copies instead of pasting. [#L39-L84, #L226-L233](https://github.com/Ryandonofrio3/Starling/blob/main/Starling/Paste/PasteController.swift#L226-L233), [FocusSnapshot.swift](https://github.com/Ryandonofrio3/Starling/blob/main/Starling/Paste/FocusSnapshot.swift)

## 3. Reuse or copy closely, versus build ourselves

### Use FluidAudio as is

- Model download, cache and loading (`AsrModels.downloadAndLoad(version: .v2)`), plus `ModelHub.offlineMode` if we ever bundle the models. It works and the alternative is plumbing.
- `AsrManager.transcribe` for the final text, and `VocabularyBoostingSession` + `CtcModels` for the word list. Call `hasCTCRescoringCandidates` first to skip the CTC pass when nothing could match. The code is current; the vocabulary doc's usage example is not.
- `VadManager` for trimming silence and deciding when a preview is worth running.
- `fluidaudiocli transcribe --model-version v2 --output-json` in a shell loop for the ~270-recording score, plus its `WERCalculator` normalisation. Or adapt Parakey's MIT benchmark harness, which already compares boosted and unboosted runs.

### Copy closely (MIT/Apache sources, keep the copyright notice)

- **Live preview loop:** Dictate Anywhere's timing (first preview at 0.5 s, then 1 s, then 2 s past 8 s, final full decode on release) and its word timeline that keeps fixed text separate from the newest guess. VoiceTypr's lessons (keep left context, do not fix words after one guess) are AGPL, so copy the idea only. Do not use `SlidingWindowAsrManager`: it shows nothing for clips under 13 s.
- **Fn hotkey:** MiniWhisper's `flagsChanged`-only tap and its Fn handling (stuck key-up recovery, swallow press and release together), changed from a toggle to hold-to-talk. Hex's 0.3 s threshold for discarding accidental modifier taps.
- **Overlay panel:** non-activating `NSPanel`, `ignoresMouseEvents`, `hidesOnDeactivate = false`, `[.canJoinAllSpaces, .fullScreenAuxiliary, .stationary, .ignoresCycle]`. The level in use ranges from `.floating` to `.statusBar` (Hex, Parakey, Starling). The settings are the same across apps; any of the MIT ones will do.
- **Clipboard:** a full snapshot of every item and type (Hex, MiniWhisper), the "transient/concealed" marker types (Parakey), and restore only while the clipboard still holds our item (the idea from VoiceInk and Fluid-oss, written ourselves). Parakey's evidence that any fixed delay can lose a race is a reason to decide the restore policy deliberately (see the open questions below).
- **Paste safety checks:** Starling's focus snapshot and secure-input check, and Parakey's "bind to the starting window, copy and notify instead of guessing".
- **Permissions:** the `AXIsProcessTrustedWithOptions` (silent check, then prompt) plus deep-link pattern, and Input Monitoring via `CGPreflightListenEventAccess` / `CGRequestListenEventAccess` (Hex, Parakey).

### Build ourselves

- **Reading text back to capture user edits.** Only VoiceInk and Fluid-oss do it, and both are GPL-3.0, so copying their code would put Fluidity under the GPL. Their designs are a guide: an Accessibility baseline about 120 ms after the paste, watching until focus leaves or 60 s pass, diffing only the pasted range, and requiring repeats or user approval before learning anything.
- **The paste sequence as a whole.** Dictate Anywhere's "press the app's own Edit > Paste through Accessibility first" (MIT) is worth testing against plain Cmd-V. The ordering, fallbacks and "never retry after an uncertain result" rule should be our own small module with tests. Hex's version shows how easily a fallback becomes unreachable.
- **Microphone capture.** FluidAudio has none. Parakey's comments list two `AVAudioEngine` traps: the converter's input block must return `.noDataNow`, never `.endOfStream`, and the tap callback must not run on the main actor. [main.swift#L13-L22](https://github.com/rcourtman/parakey/blob/main/swift/Sources/Presspeech/main.swift#L13-L22)
